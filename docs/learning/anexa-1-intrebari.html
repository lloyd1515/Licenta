A1.1. Pachetele de control, transmisia wireless și registrele de stare

Ce trebuie să studiez despre pachetele de control, transmisia wireless și registrele de stare?

Cadrele 802.11 au trei tipuri principale: management, control și date. Tabelul din [4] are și tipul 11, „Extension”, pentru cadre speciale. Primii doi octeți ai cadrului formează câmpul „Frame Control”. El spune tipul și subtipul cadrului.

Placa trimite doar probe request, adică un cadru de management (Figura A1.1). Codul citește un singur câmp de stare de la radio: rssi (Figura A1.2). Singurul „registru de stare” scris de cod este bitul WIFI_CONNECTED_BIT. Funcția xEventGroupSetBits are rolul „Set bits within an event group” [3].

src/firmware/esp32_csi_node/main/main.cliniile 47, 63–64, 98, 122, 131, 137

“The very first two octets transmitted by a station are the Frame Control. […] These three subfields consist of two bits Protocol Version subfield, two bits Type subfield, and four bits Subtype subfield.” · Tabelul: “00 | Management | 0100 | Probe Request” Traducere: primii doi octeți sunt Frame Control: 2 biți de versiune, 2 biți de tip, 4 biți de subtip. Tipul 00 cu subtipul 0100 este Probe Request. [4] Wikipedia, „802.11 frame types” · deschide la citat
“The esp_wifi_80211_tx() API can be used to: Send the beacon, probe request, probe response, and action frame.” Traducere: funcția esp_wifi_80211_tx poate trimite beacon, probe request, probe response și cadre action. [1] ESP-IDF v5.1, Wi-Fi Driver › Wi-Fi 80211 Packet Send · deschide la citat
“struct wifi_pkt_rx_ctrl_t — Received packet radio metadata header […] signed rssi — Received Signal Strength Indicator(RSSI) of packet. unit: dBm” Traducere: structura este antetul de stare radio al fiecărui cadru primit. Câmpul rssi este puterea semnalului, în dBm. [2] ESP-IDF v5.1, API Reference › Wi-Fi › Structures · deschide la citat

Observație: Studiază întâi cadrele de management, fiindcă placa trimite doar probe request. Apoi studiază wifi_pkt_rx_ctrl_t, starea radio a fiecărui cadru. Cadrele de control apar doar ca trafic primit în modul promiscuu.

A1.2. De unde vine amplitudinea?

De unde vine amplitudinea?

Amplitudinea vine din perechile I/Q. Codul o calculează cu np.abs: „For complex input, a + ib, the absolute value is √(a² + b²)” [5]. Pachetul are 128 de octeți CSI, adică 64 de perechi [1]. PC-ul păstrează 52 de coloane: pozițiile 6–31 și 33–58. Pe datele reale, 10 dintre ele sunt mereu 0. Rămân 42 de subpurtătoare utile (Figura A1.4).

A1.3. Datele sunt reale sau simulate?

A1.4. Pot lucra pe date reale? Cum le scot?

Da. Plăcile trimit pe portul 5005, către 255.255.255.255 (sdkconfig, liniile 359–360). Pașii de urmat:

  1. Porniți cele 3 plăci ESP32.
  2. Din src/, rulați python -m csi.record --duration 20 --out csi/data/captura_noua.npz.
  3. Încărcați fișierul cu np.load(..., allow_pickle=True) și citiți listele p1, p2, p3.

Important: Fără --out, fiecare rulare suprascrie csi/data/capture_real.npz.
