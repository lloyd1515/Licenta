Harta codului: main.c și csi_ui.py

Acest document explică ce face fiecare funcție. Apoi arată drumul unui pachet de la placa ESP32 până pe ecranul PC-ului. Apasă pe casete ca să vezi detaliile. La final ai un quiz cu 15 întrebări.

Partea C (ESP32) Rețea Partea Python (PC)

1. Imaginea mare

Sistemul măsoară cum se schimbă semnalul Wi-Fi într-o cameră. Mișcarea unei persoane schimbă semnalul. Placa ESP32 măsoară această schimbare. Programul Python o desenează.

Măsurătoarea se numește CSI (Channel State Information). CSI descrie, pentru fiecare subpurtătoare radio, cât de mult a schimbat canalul semnalul. Codul tău folosește 64 de subpurtătoare.

Regula de bază: un nod nu măsoară propriul semnal. Un nod măsoară semnalul primit de la alt nod. De aceea ai nevoie de cel puțin două plăci.

Cele trei părți

C

main.c

Rulează pe ESP32. Trimite probe radio. Primește probe de la alte noduri. Măsoară CSI. Trimite rezultatul prin UDP.

Rețea

Wi-Fi + UDP

Poartă pachetele de la placă la PC. Nu are cod în repo. Fișierele C și Python nu se citesc între ele.

Python

csi_ui.py

Rulează pe PC. Ascultă pe un port UDP. Verifică fiecare pachet. Desenează spectrul și cascada.

Harta generală (apasă pe casete)

Ideea cea mai importantă

C și Python nu partajează cod. Ele partajează un contract: un pachet de exact 138 de octeți, cu un format fix.

Partea C scrie pachetul în acest format. Partea Python îl citește în același format. Dacă un format se schimbă, trebuie să schimbi și celălalt.

Contractul are un tabel în secțiunea „4. Drumul datelor”.

2. main.c: ce face fiecare funcție

Fișierul are 119 de linii și 4 funcții proprii, un tip de date și un tablou.

Cum lucrează cele trei fire de execuție

După pornire, trei lucruri rulează în paralel. Fiecare are o sarcină simplă.

Task Wi-Fi (al sistemului)

Primește cadre radio. Apelează on_csi pentru fiecare măsurătoare. on_csi trebuie să fie rapidă.

probe_sender (core 0, prioritate 5)

Trimite un probe la fiecare 10 ms. Nu așteaptă niciun răspuns.

udp_sender (core 1, prioritate 10)

Așteaptă în coadă. Când apare un pachet, îl trimite prin UDP.

Coada (ring buffer, 16 KB) leagă on_csi de udp_sender_task. on_csi scrie în coadă. udp_sender_task citește din coadă. Astfel măsurarea nu așteaptă rețeaua.

Un al patrulea element, on_wifi_event, rulează în bucla de evenimente a sistemului. Se apelează când Wi-Fi pornește, se deconectează sau primește IP.

4. Drumul datelor: cum ajunge CSI din C în Python

Răspunsul scurt: Python nu citește fișierul C. Python nu vorbește direct cu placa. Placa trimite pachete UDP prin Wi-Fi. Sistemul de operare al PC-ului le pune într-o coadă a portului 5005. Python citește din această coadă.

Parcurge drumul pas cu pas

Contractul: pachetul de 138 de octeți

Apasă pe un octet ca să vezi ce câmp este. Aceeași structură există în C (csi_packet_t) și în Python (HEADER).

Apasă pe un octet.
OctețiCâmp în CÎn PythonCe înseamnă
0–1uint16_t magicH → magicValoarea fixă 0xA55A. Python respinge pachetul dacă valoarea este alta.
2uint8_t node_idB → node_idNumărul plăcii (de la NODE_ID). Python alege coloana după el.
3int8_t rssi_dbmb → rssi_dbmPuterea semnalului în dBm. Python o arată în titlu.
4–7uint32_t timestamp_usI → ignorat (_)Ora plăcii în microsecunde. Python nu o folosește acum.
8–9uint16_t seqH → seqNumăr de ordine. Python îl arată în titlu. Python nu verifică lipsa de numere.
10–137int8_t csi_iq[128]np.frombuffer(..., int8)64 de perechi (Q, I). Python calculează amplitudinea din fiecare pereche.

Semnul < din "<HBbIH" înseamnă „little-endian, fără umplutură”. ESP32 este little-endian. Structura C este packed. De aceea cele două părți au aceleași poziții.

Cum devine o pereche (Q, I) un punct pe grafic

Fiecare subpurtătoare are doi octeți: Q și I. Aceștia sunt partea imaginară și partea reală a unui număr complex.

Python calculează hypot(Q, I). Rezultatul este amplitudinea: lungimea numărului complex. Ordinea Q/I nu contează pentru amplitudine.

Python nu calculează faza. Faza ar cere ordinea corectă Q/I.

Axa X a graficului este „indexul în buffer”. Ordinea din buffer este k = 0…31, apoi k = −32…−1. Graficul nu arată frecvențele în ordine crescătoare. Subpurtătoarele inactive apar cu valori mici.

Cât de multe pachete trec

Fiecare nod trimite aproximativ 100 de probe pe secundă. Un nod primește probe de la fiecare alt nod. Cu două noduri, fiecare nod măsoară cel mult 100 de CSI pe secundă. Cu trei noduri, fiecare nod măsoară cel mult 200.

Python se redesenează de 20 de ori pe secundă. La fiecare redesenare, Python citește toate pachetele sosite în ultimele 50 ms.

8. Caiet: notițele mele

Notițe în stil de curs, scrise de mână, cu scheme. Sunt aceleași idei ca în filele de mai sus, dar condensate ca la un curs.

pag. 1

Ce măsurăm? CSI

  • CSI = cât schimbă camera semnalul Wi-Fi, pentru fiecare subpurtătoare (64).
  • Om care se mișcă → reflexii diferite → CSI diferit. Asta detectăm.
  • O placă nu își aude propria transmisie ⇒ minim 2 noduri
  • Nodul A trimite probe. Nodul B măsoară. (Și invers, amândouă fac ambele.)

!! C și Python nu își citesc fișierele. Singura legătură = formatul pachetului (138 B).

pag. 2

main.c: cine rulează unde

  • app_main rulează o dată, pornește tot, apoi iese.
  • După el: 3 lucruri în paralel. Coada le leagă.
  • De ce coadă? Nu blochez task-ul Wi-Fi cu rețeaua.
  • Timeout 0 la scriere → coada plină = pachet pierdut (+ log).
pornire: NVS → netif → event loop → coadă → wifi init → handlere → STA + parolă → 6 Mbps → start → ps NONE → promiscuu → CSI on → MAC în probe → task-uri
pag. 3

on_csi: ce decide

  • 0x40 = probe request. Placa e în mod promiscuu, vede tot → filtrez.
  • Verific doar tipul, nu sursa ⇒ un telefon cu probe OFDM ar intra și el.
pag. 4

Contractul: 138 B

  • Ordinea subpurtătoarelor în buffer: k = 0…31, apoi −32…−1 (nu e în ordine de frecvență).
  • Python verifică: len = 138 și magic = 0xA55A, altfel aruncă tăcut.
  • Python ignoră timp, nu calculează faza.
  • Doar 52 din 64 subpurtătoare sunt active → restul ≈ 0 (normal).
pag. 5

csi_ui.py: bucla de 50 ms

  • Socket UDP non-blocant → fereastra nu îngheață.
  • QTimer 50 ms ⇒ 20 desenări/s, indiferent de câte pachete vin.
  • Coloana: sus = ultimul pachet, jos = cascada ultimelor 300 (nou = sus).
  • Coloane noi în ordinea sosirii primului pachet.
  • Atenție: show se apelează doar când vin pachete noi.

Recapitulare în 6 rânduri

  • A trimite probe OFDM la 6 Mbps → B primește → hardware estimează canalul din LLTF.
  • on_csi (rapidă) → pachet 138 B → coadă.
  • udp_sender_task → sendto → AP → PC, port 5005.
  • Nucleul păstrează datagramele în coada socket-ului.
  • refresh la 50 ms golește socket-ul, validează (138 B + magic), calculează amplitudinea.
  • O coloană/nod: spectru sus, cascada de 300 jos.
